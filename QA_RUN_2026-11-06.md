## 2. Critical — must fix before launch

### C1. A match result can be applied twice — ratings, wins and rounds corrupt · LIVE
`apps/api/src/lib/match-outcome.ts:153` completes the match with `UPDATE … WHERE id=$2` and no status guard (same in the rematch branch, line 58).
- **Repro:** `PUT /admin/matches/:id/result` twice on an in-progress tournament match.
- **Observed:** player rating 920 → 950 → 980; wins 2 → 3 → 4; round 101 → 102 → 103; participant status flipped from `knockout` back to `active`. Flipping the winner afterwards left the phantom wins and marked the original winner `eliminated`.
- **Also reachable without an admin (NLC):** a human chasing a bot submits a score while the headset polls `GET /integrations/meta/matches/current`; `playPendingBotInnings` (`meta.service.ts:245`) resolves the same match again.
- **Fix:** `… WHERE id=$2 AND status IN ('confirmed','in_progress','pending_confirmation') RETURNING id`; return early on 0 rows. Reject `setResult` on completed matches unless the admin explicitly reverses the old outcome.

### C2. Venue/tournament admins act and read outside their scope · LIVE
| Action | Who | Result |
|---|---|---|
| `POST /venues/{otherVenue}/slots` (public route) | venue_admin of venue A | **201** — slot created in venue B |
| `POST /venues` (public route) | venue_admin | **201** — new venue created (admin route is superadmin-only) |
| `POST /tournaments` (public route) | tournament_admin | passes role check (400 only on body) |
| `GET /admin/bookings` | tournament_admin | 41 of 42 rows out of scope, **22 player emails** |
| `GET /admin/matches` | tournament_admin | 64 of 87 rows out of scope |
| `GET /admin/notifications` | tournament_admin | 100/100 — every user's notifications |
| `GET /admin/slots` | venue_admin | 440 of 500 rows out of scope |
| `GET /admin/tournaments` | venue_admin | 48/48 incl. drafts |

Root cause: `slots.routes.ts:26`, `venues.routes.ts:34`, `tournaments.routes.ts` use `requireRole(...)` only; admin list services never receive `adminScope`. **Fix:** delete the public create routes (admin routes already exist) and filter every admin list by `venue_id = ANY($scope)` / `tournament_id = ANY($scope)`.

### C3. Editing a tournament shifts all its dates on every save · CODE
`apps/web/src/pages/admin/TournamentFormPage.tsx:120-123` fills `datetime-local` inputs with `iso.slice(0,16)` (UTC); the browser reads that as local time and `toTournamentApiBody` converts back to UTC. An admin in Pakistan (UTC+5) who opens **Edit → Save** without touching anything moves start, end and both registration dates 5 hours earlier — again on every save. **Fix:** format with local getters into `YYYY-MM-DDTHH:mm`.

### C4. The last superadmin can demote themselves — permanent admin lockout · LIVE
`PATCH /admin/users/{ownId} {"role":"player"}` → **200**. The very next request is a player; nothing in the app can restore a superadmin. This happened during testing and needed a database reseed to recover. (Self-*delete* is correctly blocked with 409.) **Fix:** reject role changes on self and any change that leaves zero active superadmins.

### C5. Tournament lifecycle has no transition guards · LIVE
A **completed** tournament: `POST /publish` → 200, status becomes `open`; `POST /start` → 200, status becomes `in_progress`. Also (CODE, `admin/services/tournaments.service.ts:179-231`): `start()` works on drafts; `complete()` leaves rounds and matches open until the 60 s sweep, so a late score re-activates a player in a finished tournament and the one-live-tournament index then blocks them from registering anywhere; `delete()` cascades paid `buybacks`, nulls live matches' `tournament_id`, and always 409s if a bot played. **Fix:** explicit from→to allow-list; `complete()` closes rounds and expires matches in one transaction; block delete when matches or buybacks exist.

### C6. Stripe: a player can be charged and get nothing, with no refund path · CODE
- Card declined → `payment_intent.payment_failed` marks the buyback `failed`; player retries in the same Payment Element, payment succeeds → success on a `failed` buyback is ignored (`lib/stripe.ts:150,163-168`).
- Player cut from T1 joins T2, then buys back into T1 → fulfilment hits the one-live-tournament unique index → webhook returns 400 → Stripe retries for 3 days (`tournaments.service.ts:1030`; checkout never calls `assertNoOtherLiveTournament`).
- Payment lands after the round closed → buyback stuck `pending`.
- In every case admin refund refuses: it only refunds `completed` buybacks (`buybacks-notifications.service.ts:131`).

**Fix:** `succeeded` wins over `failed`; check live-tournament at checkout and inside fulfilment; auto-refund when fulfilment is impossible; allow refund of any buyback with a succeeded PaymentIntent, with an idempotency key.

## 7. What held up (tested and passed)

- **Auth:** `alg=none` and tampered-role JWTs rejected; garbage tokens → 401; refresh tokens single-use; access token dead after logout; refresh cookie `HttpOnly; SameSite=Strict; Path=/api/v1/auth`; per-IP (50/5 min) and per-account (10/15 min) login limits work; identical error text for unknown vs wrong password; email login is case-insensitive; duplicate email/username rejected case-insensitively; admin-created mixed-case emails can log in.
- **Player IDOR:** reading/confirming another player's match → 403; cancelling another's booking → 404; marking another's notification read → 404; player and anonymous users blocked from all 13 admin areas.
- **Input handling:** malformed JSON → 400; bad UUIDs → 400; SQL-ish IDs → 400; absurd paging rejected; 3.9 MB body handled; prototype pollution has no effect; all SQL parameterised.
- **Concurrency:** 15 simultaneous bookings (5 users × 3) for a 1-seat slot → exactly 1 success, counters correct; 4 parallel cancels → 1 success; 10 parallel queue joins → 1 entry; tournament `max_players` and duplicate Stripe webhooks are row-locked.
- **Public profile** exposes no email/location/rating internals. Stripe webhook rejects unsigned calls.
- **Responsive layout:** **zero horizontal overflow** across all 36 routes at 360 / 768 / 1366 px; admin tables scroll inside their containers; **zero console errors** on any page. React Query devtools are dev-only.
- **Production edge:** API sends full helmet headers; CORS allows only `https://tournament.pixelpaddle.com`; TLS 1.0/1.1 refused; HTTP → HTTPS redirect; no `.env`/`.git` exposure.
